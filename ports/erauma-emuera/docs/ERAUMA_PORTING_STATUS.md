# 이식 현황 — 2026-10-01, 포트 0.3.2

원본 era말딸을 관리형 JavaScript 실행기로 Emuera.NET에 연결하는 게임 실행용 호환판이다. 원본 `sources/erauma`와 기존 `docs/`, `game/`, `dev/`, `test/`는 변경하지 않았다. CrossWorld.Core 공용 인물·세계 통합은 이번 범위에 포함하지 않는다.

실행 기준은 **EraUma v3.113 (ryuki)**와 공식 **res 20260923**이다. 46종의 게임 사용 Era API는 원본 API 구현과 호스트로 처리한다. 원본 게임 CommonJS와 데이터 표를 읽고 322개 kojo를 원본 컴파일러로 생성하며, 게임 실행에는 EraElectron과 Node.js가 필요하지 않다. 단독 실행 구조와 선정한 게임 경로의 검증을 유지하고 0.3에서 화면·그림·음향 연결을 추가했다. **새 UI의 전체 직접 플레이는 아직 미확인**이다.

## 0.3.2 레이스 화면 갱신 수정 — 자동 검사 PASS

사용자는 0.3.1이 이전보다 부드러워졌다고 보고했지만 레이스 화면 전체가 주기적으로 사라지는 깜빡임은 영상에서 확인됐다. 60fps·310프레임·5.1667초 중 빈 화면은 114프레임(36.8%)·45구간이며, 각 구간은 약 17–67ms다. 이 결과는 이전 그림이 계속 남는 화면 중첩과 구별한다.

실행기는 이미 double buffering을 사용한다. `api.ClearDisplay` (`EmueraConsole.ClearDisplay`)가 모든 행과 여백을 재출력하기 전에 강제 paint를 수행해 빈 canvas를 노출한 것이 원인이다. 0.3.2의 `NativeFrameUpdate`는 엔진의 `console.SetRedraw(0)` 플래그와 managed `PictureBox.Paint` 처리로 갱신 중 이전 완성 bitmap을 유지한다. 마지막에 handler와 엔진 갱신 상태를 복원하고 완성 프레임을 강제 출력한다. 일반 버튼·스크롤은 갱신 범위 밖에서 native 경로를 유지한다.

## 0.3.1 수정과 자동 검증의 역사적 근거

**0.3.0의 사용자 직접 시험은 실패했다.** 대사는 빈 화면 클릭으로 진행되지 않고 Enter만 반응했으며, 선택할 때 이전 그림·버튼이 겹쳐 남아 레이스 전에 시험을 중단했다. 자동 canvas 시험이 실제 입력 출력을 통과하지 않아 놓친 결함이다.

0.3.1은 대사 진행을 `WAIT`/`TWAIT`로 분리하고 번호 선택·자유 문자열·입력 규칙·현재 URL을 `INPUTS`/`TINPUTS`로 유지한다. 읽기 전용 `input-kind` 조회를 추가했으며 화면 갱신 전에 실행기의 입력 출력 줄을 제거한다.

| 검증 | 현재 결과 | 범위 |
|---|---|---|
| 원본 모집 화면의 실제 `INPUTS` 출력·부분 갱신 | PASS (자동 재현) | 입력 출력 `[1,1,1]`줄. 수정 전 미관리 줄 `[0,1,2,3]`, 수정 후 `[0,0,0,0]` |
| 호스트 UI 회귀 확장 | PASS | 21개: 대사 대기·선택·자유 문자열·`any`+규칙·URL 구분 포함 |
| 일반 게임 입력 루프의 native 클릭 처리 | PASS (관리형 엔진 검사) | `INPUTS` 빈 클릭 차단 대조, `WAIT` 빈 클릭, `TWAIT` 시간 초과 뒤 빈 클릭, 번호 7·`any` 선택 8·타이머 선택 9·`Trainer` 입력과 URL 값 입력 유지 |
| 기존 자동 회귀 재실행 | PASS | 기본 10·API 21·저장 10·선정 플레이 46, 정확한 실행기 7단계, 원본 canvas 23개 |
| 수정 후 사람이 수행하는 전체 시나리오 | 미확인 | 레이스·저장·완전 종료·재실행·로드·후속 행동 포함 |
| 실제 음향 청취 | 미확인 | 이전 음량 0 자동 시험과 구별 |

0.3.1 증거는 `docs/evidence/0.3.1/`에 따로 기록한다. 입력 루프 검사는 격리한 시험 프로세스 내부의 관리형 입력 처리 검사이며 OS 입력이나 사람의 직접 클릭은 아니다. 자동 회귀의 성공만으로 UI 완료를 판정하지 않는다.

화면 검증은 고정 실행기의 실제 renderer와 canvas 출력에 대한 자동 검사다. 바탕화면 캡처·직접 클릭·음향 청취를 대신하지 않는다. 새 UI 기능별 구현 수준과 의뢰 항목의 남은 조건은 [UI 현황](ERAUMA_UI_STATUS.md), [재작업 기준](ERAUMA_SECOND_WORK_ORDER.md)에 있다.

일반 게임은 표시 지연을 실제 타이머로 처리해 레이스 재생을 단계별로 갱신한다. 빠른 호스트 회귀와 canvas 검증의 가상 시간 전진은 시험 전용이다. 원본 레이스가 전달하는 숫자 문자열을 포함해 그래프의 전체 계열을 출력한다. 0.3.0 확정 증거의 보관 위치는 `docs/evidence/0.3/`이며 아래 0.2 기록과 구별한다. 당시 canvas 보고서는 `artifacts/runtime-UiScreens-fce0e490/results/ui-summary.json`과 `artifacts/runtime-UiScreens-9717a264/results/ui-summary.json`, native 음향 보고서는 작업 폴더의 `outputs/native-ui-audio-0027b902/native-ui-summary.json`이다. 당시 최종 회귀와 음향 시험의 플러그인 DLL SHA256은 `A2CD368A8073B05122C005C289D39F07238B9F2ABA4771DA4C4AB97D823F5F25`로 같다. 자원 포함 ZIP의 이동 실행 근거는 `docs/evidence/0.3/package-relocation-preflight.json`에 있으며 같은 플러그인·원본 게임·공식 자원을 사용했다.

| 모든 스토리·모든 캐릭터·원본 Electron과 동일 난수 비교 | 미수행 | 선정한 경로 검증과 별개이며 전수 호환을 보증하지 않음 |

직접 입력 항목은 사용자 확인과 결과 파일을 근거로 한다. Windows 화면 캡처 도구가 시간 초과됐으므로 자동 화면 조작으로 확인했다고 기록하지 않는다. 계산·새 게임·휴식 시험은 ERB 값을 주입하며, 훈련·레이스 시나리오는 실제 Emuera 플러그인 안에서 원본 메뉴를 자동 실행한다. 후자의 모든 중간 화면을 Emuera에 그리거나 사람이 클릭한 것은 아니다. 원본 게임 실행·입력 연결·텍스트 출력의 검증과 모든 화면의 직접 조작 검증을 구별한다.

실행기 자동 시험 7단계를 통과했다. 타이머·플레이 시나리오·별도 프로세스 복원·quit 시험은 정상 UI 종료를 기다려 `emueraExited:true`, `processExitCode:0`을 확인한다. 기존 계산·휴식·체크포인트 시험의 최종 화면에 남은 프로세스는 보고서 뒤 시험이 정리한다. 재시작 검증은 새 Emuera 프로세스로 실행한다.

원본 메뉴에서 테이오를 모집·선택하고 주차별 원본 이벤트를 거쳐 게임 표시 24주차의 데뷔 레이스까지 진행했다. 이 경로에서 원본 저장 메뉴로 만든 시험 상태를 `tests/fixtures/`에 분리했다. 재현 시나리오는 그 저장을 임시 폴더로 복사해 원본 제목·로드 메뉴를 사용하며, 시험 안에서만 난수 seed 17을 적용한다.

재현 시나리오의 스피드 훈련은 speed 121.6→136.3, 트레이너 에너지 810→650으로 상태를 바꿨다. 등록된 원본 데뷔 레이스를 계산하고 스피드 결과 수치를 열어 1위의 `RaceHistory` 기록, 등록 초기화, 주 메뉴 복귀를 확인했다. 훈련 후 슬롯 5와 경기 후 슬롯 6을 원본 저장 메뉴로 기록하고, 별도 프로세스의 원본 제목·로드 메뉴에서 능력치·경기 이력과 전체 저장 상태를 복원한 뒤 휴식 행동을 계속했다. 일반 게임의 난수와 경기 계산은 바꾸지 않았다.

## 0.2 시험과 증거

- 기본 호스트 시험: 10개 검사 통과; JS 계산, 출력, 데이터 타입, 비동기 입력, 새 엔진 저장 복원과 잘못된 API·타입 거부
- `--api`: 21개 검사 통과; 화면 논리 행·부분 삭제·교체, 버튼·정규식·문자열, 입력 교체, 타이머 추가·취소와 기존/늦은 버튼의 동시 활성화, 없는·손상된·다른 게임·낮은 버전 저장의 실패 보고와 계속 진행, 알림의 행 수 보존
- `--save`: 10개 검사 통과; 원본 JSON/gzip 세이브와 global·중첩 게임 데이터 복원
- `--play`: 46개 검사 통과; 원본 새 게임·휴식·전체 상태 복원과 정상 quit 요청
- `--scenario`: 20개 검사 통과; 원본 훈련·레이스·저장·로드 메뉴와 전체 저장 복원
- `--scenario ... restore`: 별도 프로세스에서 5개 검사 통과; 경기 후 저장 복원·로드 메뉴·이후 행동·정상 quit 요청
- 실제 Emuera: 7단계 통과; CALLSHARP 계산 연결, 원본 새 게임·행동·체크포인트 복원, 실시간 타이머, 훈련·레이스 시나리오, 별도 프로세스 메뉴 복원·후속 행동, 정상 종료

검증 명령은 [포트 README](../README.md)에 있으며 실행 패키지에서는 `adapter-source/README.md`에 있다. 확정된 실행 보고서는 저장소의 `ports/erauma-emuera/docs/evidence/`에 보관하며 실행 패키지에 시험 저장·보고서를 포함하지 않는다. 호스트 시나리오는 `scenario-host.json`·`scenario-host-restore.json`, 실제 플러그인 시나리오는 `scenario-native.json`·`scenario-native-restore.json`에 검사와 수치가 있다. 실행기 7단계 결과는 `bridge.json`, `play.json`, `restart-restore.json`, `timer.json`, `scenario-runtime.json`, `scenario-restart-runtime.json`, `quit.json`이다. 직접 입력은 `interactive.json`, 환경·검증 방법은 `environment.json`에 기록했다.

출력문만 생성됐는지 보는 시험과 메뉴 버튼·수치 변화·전체 상태 일치를 보는 시험을 구별한다. API 정적 조사 목록도 실행 커버리지와 구별한다. 선정 경로가 성공했다는 결과를 모든 스토리 분기의 전수 호환 보증으로 확대하지 않는다.

실행 패키지의 이동 가능한 구조를 검증한 보고서는 저장소의 `ports/erauma-emuera/docs/evidence/package-relocation-preflight.json`이다. 패키지 안의 상대 경로를 유지한 채 폴더를 이동해 원본 제목과 정상 종료를 확인했다. 이 보고서는 마지막 타이머 버튼 갱신 보완 전의 구조 사전 검증이며 최종 ZIP의 파일·DLL 버전을 증명하는 보고서와 구별한다. 최종 ZIP의 포함 파일 버전과 SHA256은 그 패키지의 `package-manifest.json`으로 확인한다.

## 0.2 성능 관찰

이 PC의 고정 난수 호스트 시나리오에서 초기 로딩 약 11.9초, 훈련 153ms, 레이스 4.27초, 저장 메뉴 합계 116ms, 새 엔진 생성·로드 흐름 합계 8.28초, 전체 29.9초를 관찰했다. 프로세스 working set 약 2.55GB는 여러 JS 엔진으로 원본 저장을 반복 비교하는 시험의 값이며 단일 게임의 지속 사용량이나 최고 메모리가 아니다.

별도 프로세스 복원 시험은 초기 로딩 약 7.37초, 로드 합계 1.19초, 전체 8.64초였으며 working set 약 944MB였다. 타이밍은 해당 PC와 선정 경로의 관찰값이고 성능 보증치가 아니다. 초기에는 낮은 256MB 할당 제한과 짧은 시간 제한으로 부팅이 실패해 게임 프로파일을 최대 2GB 할당·호출당 180초로 분리했다.

장기 메모리 증가와 다수 캐릭터의 부하, 저메모리·32비트 환경은 검증하지 않았다. 단계별 관찰값은 `evidence/scenario-host.json`, `evidence/scenario-host-restore.json`에 기록한다. 원본을 ERB로 전면 재작성해야 하는 런타임 제약은 발견하지 않았다.

## 남는 차이

0.3은 1차판에서 생략했던 공식 그림·여러 열·진행 막대·전체 계열 그래프와 음향 연결을 제공한다. EraElectron의 CSS와 픽셀 단위로 같지는 않으며 GIF 애니메이션·SVG·오디오 fade·CSS hover·그래프 mouseover/주석은 제공하지 않는다. WebP 실제 출력은 미확인이고 배경·오버레이의 position/fit은 부분 구현이다. Shift/연속 진행·UI 자동 넘김은 재현하지 않지만 일반 게임의 표시 지연과 늦은 선택지 타이머는 실제 시간을 사용한다. 원본 규칙·저장 구현을 유지한다. 원본 Electron과 실제 세이브의 양방향 비교 및 모든 스토리 분기 전수 검증은 수행하지 않았다. 자세한 내용은 [알려진 제한](ERAUMA_KNOWN_ISSUES.md)에 있다.
