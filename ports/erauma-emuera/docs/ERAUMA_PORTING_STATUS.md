`tests/Program.cs` 기본 시험 10개, 저장 시험 10개를 제공한다. `--play`는 새 게임·휴식·전체 상태 복원과 각 입력 경계를 검사한다. 실제 실행 결과는 `evidence/`에 있다. 출력문 생성만 검사하지 않고 메뉴 버튼 존재·변수 변화·복원 데이터 전체 일치도 검사했다.

## 성능 관찰

이 PC의 호스트 시험에서 새 게임·휴식·저장·새 엔진 로드까지 약 11.4초, 프로세스 working set 약 974MB를 관찰했다. 이 수치는 두 JS 엔진이 공존하는 시험이며 단일 게임의 지속 메모리 사용량 또는 최고치가 아니다. 초기 로딩은 재측정 시 약 10~11초였다. 최초의 낮은 256MB 할당 제한과 짧은 실행 제한으로 부팅이 실패해 게임 프로파일은 할당 제한 2GB, 호출 제한 180초로 분리했다. 장기 메모리 증가·레이스 연산 성능은 미검증이다.

## 다음 검증 순서

1. `runtime-Interactive`에서 Add 5 버튼 및 직접 5 입력 확인, `runtime-Game`에서 이름 문자열 입력 확인.
2. 부분 clear/replace의 행 단위 화면 처리를 보완하고 실제 메뉴의 정상 종료 확인.
3. 캐릭터 모집·훈련·시간 경과·레이스 완료를 실제 게임 흐름으로 검증.
4. 저장 메뉴를 통한 저장과 재실행 후 원본 로드 메뉴 복귀 검증. 현재 재시작 시험은 원본 저장 API를 bridge에서 직접 호출한다.
5. 원본 Electron과 동일 초기값/난수 조건에서 계산 결과·세이브 양방향 비교.

원본을 ERB로 전면 재작성할 근거는 발견하지 않았다. 관리형 JS 호스팅 방식의 기본 진행 가능성은 확인했으나, 최종 플레이 가능 판정에는 위 검증이 남아 있다.
