# EraUma 2차 UI·리소스 재작업 기준

기록일: 2026-10-01, 포트 0.3.2. 이 문서는 사용자가 제공한 「EraUma → Emuera.NET 호환판 2차 재작업 의뢰서」의 요구를 구현·검증 항목으로 정리한 것이다. 의뢰서 원문은 `889b6fb0-1efd-4221-bbb0-7270039449d5/붙여넣은 텍스트.txt`를 전체 읽어 반영했다. 최신 구현 수준은 [UI·리소스 현황](ERAUMA_UI_STATUS.md)에 기록하며, **0.3.0 직접 시험 실패와 0.3.1 레이스 깜빡임이 확인됐고 이번 재작업의 완료 판정은 아직 하지 않았다.** 실제 엔진의 자동 UI·canvas 확인과 사람이 직접 하는 전체 플레이를 구별한다.

## 0.3.1 레이스 깜빡임과 0.3.2 재검증 기준

사용자는 0.3.1이 이전보다 부드러워졌다고 보고했지만 레이스에서 canvas 전체가 주기적으로 사라지는 현상이 남았다. 60fps·310프레임·5.1667초 영상에서 빈 화면 구간 45회·114프레임(36.8%), 구간당 약 17–67ms를 확인했다. 이전 그림이 계속 겹쳐 남는 현상과 구별해 레이스 화면 갱신 결함으로 기록한다.

실행기는 이미 double buffering을 사용한다. `api.ClearDisplay` (`EmueraConsole.ClearDisplay`)가 모든 행과 여백의 재출력 전에 강제 paint를 수행한 것이 원인이다. 0.3.2의 `NativeFrameUpdate`는 엔진의 `console.SetRedraw(0)` 플래그와 managed `PictureBox.Paint` 처리로 교체 중 이전 완성 bitmap을 유지한다. 마지막에 handler와 엔진 갱신 상태를 복원하고 완성 프레임을 강제 출력한다. 일반 버튼·스크롤은 갱신 범위 밖에서 native 경로를 유지해야 한다.

`./ports/erauma-emuera/tools/Test-FramePaint.ps1`은 정확한 배포 실행기의 Paint callback과 native/수정된 `PictureBox.OnPaint` delegate 연결을 시험 bitmap에 기록했다. 0.3.1 대조는 7회 전환의 중간 그림 165회로 예상 FAIL(`outputs/frame-paint-6b0c25c1/summary.json`), 수정판은 전체·부분·추가 출력·표시 지연을 포함한 같은 7회 전환의 중간 그림 0회로 PASS(`outputs/frame-paint-6134aec5/summary.json`)다. 모든 최종 그림 변경·타이머 진행·handler 수 2→2·이후 새로고침 3회의 복원을 확인했다. PNG 기록이 callback을 늦추므로 165회는 실제 화면 fps가 아니며 데스크톱 캡처·OS 입력·사람의 직접 플레이 결과와 구별한다.

원본 레이스 연속 20회 갱신도 중간 그림 0회·모든 최종 그림 변경·native Paint 40회·handler 2→2·이후 새로고침 3회 복원으로 PASS했다(`outputs/frame-paint-9860cf1a/summary.json`). `Test-FramePaint.ps1 -OriginalRace`의 500ms 가상 시간 전진은 격리한 fixture 시험에만 사용하고 별도 실제 실행기의 타이머는 실제 경과 시간으로 통과했다.

0.3.2는 호스트 기본 10개·API 21개·저장 10개·플레이 46개·UI 21개, 입력 출력 4프레임의 미관리 행 0, 입력 루프 7단계와 타이머 tick 1회, 원본 canvas 23개(전체 26회·부분 27회·205행 보존·경고 0), 실행기 7단계를 통과했다. 근거는 [0.3.2 검증 요약](evidence/0.3.2/README.md)에 있다. 같은 배포 구성의 공백 경로 이동 검사에서 원본 화면 23개와 레이스 연속 갱신 20회가 PASS했다. ZIP의 개별 파일 해시는 `package-manifest.json`과 생성 검증 보고서로 확인한다. 새 수정의 자동 근거와 별도로 전체 직접 레이스 → 저장 → 완전 종료 → 재실행 → 로드 → 후속 행동, 실제 음악 청취를 기록해야 한다. 이전 자동 PASS와 0.3.1이 더 부드럽다는 피드백만으로 이 조건을 완료 처리하지 않는다.

## 0.3.0 실패와 0.3.1 수정의 역사적 근거

사용자는 빈 화면 클릭으로 대사가 진행되지 않고 Enter만 반응하며, 선택하면 이전 그림·버튼이 겹쳐 남는다고 보고했다. 캐릭터 모집 화면의 중첩으로 레이스 전에 직접 시험을 중단했다. 이 결과는 **FAIL**이며 전체 경로를 수행하지 못했다. 기존 자동 PASS는 실제 `INPUTS`의 입력 출력과 빈 클릭을 통과하지 않아 문제를 놓쳤다.

0.3.1은 대사 진행을 `WAIT`/`TWAIT`로 분리하고 선택·자유 문자열·입력 규칙·현재 URL은 `INPUTS`/`TINPUTS`로 유지한다. 실제 입력 출력 줄을 갱신 전에 제거해 이전 그림·버튼이 남는 문제를 수정했다. 원본 모집 화면의 실제 입력 자동 재현은 수정 전 미관리 줄 `[0,1,2,3]`, 수정 후 `[0,0,0,0]`과 입력 출력 `[1,1,1]`줄을 확인해 PASS했다. 21개 호스트 UI 회귀와 `Game.ERB` 입력 루프의 관리형 엔진 검사도 PASS했다. 후자는 이전 `INPUTS` 빈 클릭 차단 대조, `WAIT`·시간 초과 뒤 `TWAIT` 빈 클릭, 번호·문자열·타이머 선택·URL 값 입력 유지를 검사한 시험 프로세스 내부 검사이며 사람의 클릭이나 OS 입력 시험이 아니다.

수정 후 빈 클릭 진행·모집 선택의 중첩 제거부터 다시 확인해야 한다. 이후 아래 전체 직접 경로·저장 후 완전 종료와 재실행·로드·실제 음향 청취를 확인하기 전에는 완료로 표시하지 않는다.

## 기준과 변경 범위

실행 기반은 저장소의 **EraUma v3.113 (ryuki)**이고 공식 리소스 기준은 **20260923**이다. 게임 실행 구조를 `Emuera.NET → CALLSHARP → C# compatibility → Jint → 원본 EraUma JavaScript`로 유지한다. 육성·이벤트·레이스·캐릭터·저장·Kojo 규칙을 UI 계층에 복제하거나 ERB로 재작성하지 않는다.

포트 소스와 문서는 `ports/erauma-emuera/`에 둔다. 보존된 `sources/erauma`와 저장소 루트의 `docs/`, `game/`, `dev/`, `test/`는 변경하지 않는다. 공식 이미지·오디오는 별도 설치·런타임 캐시로 관리하고 Git 소스에 추가하지 않는다.

기존 한국어판 `E:/Download/eraumak-main.zip`은 의뢰서상 v2.210 (agito) 기반의 참고 자료다. 파일 존재와 크기 61,118,473 bytes를 확인했다. 최신 실행 기반으로 사용하거나 최신 원본 위에 덮어쓰지 않는다. 한국어 완역은 이번 범위에 포함하지 않으며 미래 `ko-KR` 언어팩으로 분리할 수 있는 구조를 보존한다.

## 현재 확보된 리소스 근거

공식 [uma-resource 저장소](https://gitgud.io/umaera/data/uma-resource)의 20260923 태그 `db8aab4015bc137ab02af1dd940e35ab84bd1f22`를 확인하고 LFS 파일을 포함한 ZIP을 내려받았다. 원본 `build/static.json`과 설치된 CSV를 이용한 연결 결과는 **이미지 2,786개·오디오 22개·CSV 66개, 누락/경고 0개**다.

ZIP은 431,787,981 bytes이며 SHA256은 `c21debd728dc934c637c93af4ef6b7fa7e0a32177e134b151a2a47036405642b`다. `artifacts/resources/resource-install.json`에는 설치 2,859개·435,577,015 bytes와 비자원 개발 파일 6개의 제외 목록이 있다. 단일 파일 100 MB를 넘어 제외한 항목은 없다. 이 증거는 자원 확보와 매핑에 관한 것이며 실제 native 이미지·음향 또는 전체 UI 완료 증거가 아니다.

`tools/Install-Resources.ps1`은 자원 파일을 지정 루트의 `res/` 안에만 설치한다. ZIP 경로 탈출·중복·링크를 거부하고 파일·전체 크기를 제한하며 사용자 저장을 설치 대상으로 삼지 않는다. `ResourceCatalog.cs`는 존재하는 로컬 파일과 원본 crop 메타데이터를 연결한다. 원본에 선언된 HTTP(S) 경로의 캐시만 선택적으로 지원하며 현재 static 매핑의 HTTP URL은 0개다.

## 현재 의도적 차이와 미완료 항목

24열 geometry를 Emuera의 native HTML·sprite로 변환하므로 EraElectron의 CSS와 픽셀 단위 동일성을 보장하지 않는다. 허용 범위는 원본 화면의 정보 영역과 행동 흐름이 대응되는지로 판단한다. GIF는 정지 프레임이고 JPEG·WebP는 엔진 decoder 경로를 사용하지만 실제 WebP 출력은 미확인이다. SVG·오디오 fade·CSS hover·그래프 mouseover/주석은 미구현이다. 배경·오버레이 opacity는 연결했고 position·fit은 부분 구현이다. 정확한 배포 실행기의 Sound는 Windows Media Player 변형이며 위치 증가·pause 유지·resume·실제 loop 경계·Dispose·재시작 없는 실행 중 음량 변경·오류/경고 0을 자동 확인했다. 0.3.0 native 보고서는 작업 폴더의 `outputs/native-ui-audio-0027b902/native-ui-summary.json`이다. 시험 음량은 0이므로 실제 음향 청취는 미확인이다.

native UI probe는 색상·24열·3개 정렬 행·crop·레이어·2계열 모든 점·버튼 hit ID와 진행 막대 65/0/100%·높이 6px·offset의 5개 픽셀 검사를 통과했다. 새 게임·원본 타이틀·메인·훈련·정보·아이템·외출·상점·레이스 진행/재생·결과·저장을 포함한 23개 실제 소프트웨어 canvas 경로를 자원 있음/없음 양쪽에서 검사했다. 테이오 공식 아이콘·4열 메뉴·상단 배치를 확인했다. 자원 있음 `runtime-UiScreens-fce0e490`은 전체 갱신 27회·부분 갱신 27회·205행 보존, 자원 없음 `runtime-UiScreens-9717a264`는 전체 갱신 26회·부분 갱신 27회·205행 보존이다. 원본 공식 리소스 URL `https://umaera.gitgud.site/data/uma-resource/full.html`의 shell 브라우저 실행도 자동 검사에서 PASS다. 사람이 URL 버튼을 직접 클릭해 브라우저 열기·복귀하는 시험은 미확인이다. 이 결과를 위 직접 기록 표의 PASS로 기입하지 않는다.

0.3.0의 기본 10개·API 21개·저장 10개·플레이 46개, 자원·i18n·UI 16개, 시나리오 20개·별도 프로세스 복원 5개는 PASS였다. 당시 코드 동결 후 같은 플러그인 DLL로 최종 호스트 회귀와 실제 Emuera 7단계도 PASS했다. 그 최종 회귀와 native 음향 시험의 플러그인 DLL SHA256은 `A2CD368A8073B05122C005C289D39F07238B9F2ABA4771DA4C4AB97D823F5F25`로 같다. 이 역사적 근거는 `docs/evidence/0.3/`에 보존하고 0.3.1 결과는 `docs/evidence/0.3.1/`에 구별해 기록한다. 0.3.0 자원 포함 ZIP의 전체 파일 해시·상대 경로·사용자 저장 미포함 검사와 공백이 있는 별도 폴더에서의 7단계 회귀·23개 화면도 통과했다. 이 자동 결과로 직접 시험 실패를 지우지 않는다.

부분 갱신은 실행기의 입력 출력 줄을 제거한 뒤 같은 정적 선두 행을 보존하고 이후 native 행만 삭제·교체하며 버튼 행은 현재 입력 세대에 맞춰 다시 출력한다. 완전히 바뀐 화면과 sprite 캐시 정리에는 전체 redraw가 필요하다. 일반 게임의 `era.delay()`는 실제 타이머로 처리해 레이스를 단계별로 재생한다. 빠른 호스트 회귀의 표시 지연 생략과 `skip-text`·`ui-return-main`·`ui-advance`의 가상 시간 전진은 검증 전용이며 일반 `Game.ERB`는 `AWAIT`/`TINPUTS`/`TWAIT` 50ms와 `tick`을 사용한다. 폰트·창 크기·긴 문장·스크롤과 늦은 버튼의 직접 조작은 별도로 확인해야 한다.

원본 레이스의 숫자 문자열을 포함한 전체 dataset과 단계형 곡선을 그린다. `game/language-packs/<locale>/entry.js`를 읽는 독립 loader는 임시 시험팩으로 검증했으며 신규 `ko-KR` 완역은 미구현이다. 실행 패키지는 공식 `game/res/`를 포함하고 설치·다운로드 안내와 상대 경로를 제공한다. 이전 ZIP 이동 실행은 자동 검증 근거로 보존하며 0.3.2의 배포 구성도 별도 공백 경로에서 23화면·레이스 20회 갱신을 통과했다. 사람의 전체 직접 플레이와 실제 음악 청취도 남아 있다.

기존 1차 자동 시험 근거는 0.2 역사 기록으로 보존한다. 모든 스토리·언어·설정·장기 메모리와 원본 Electron의 동일 난수·세이브 교차 비교도 완료됐다고 주장하지 않는다.

## 완료 판정

최신 코드에서 기존 자동 시험과 새 res/UI/URL/음향 검증을 통과하고, 위 직접 시나리오 결과와 해결하지 못한 차이를 기록한 뒤, 이동 가능한 새 실행 ZIP을 확인해야 한다. 구현 상태를 [현황 문서](ERAUMA_UI_STATUS.md)에 갱신하고 자동·직접 근거를 함께 제출한다. 이 조건을 충족하기 전에는 2차 UI 포팅을 최종 완료로 표시하지 않는다.
