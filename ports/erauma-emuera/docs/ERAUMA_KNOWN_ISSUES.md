# 알려진 문제와 제한

- **직접 입력 미확인:** 자동 ERB 문자열 주입과 Promise 재개는 통과했지만 실제 INPUTS 입력창·숫자 버튼 클릭은 확인하지 못했다. Windows Computer Use의 실행 요청이 `launched app did not expose a targetable window`를 반환했고 재조회에도 대상 창이 없었다. 이를 사용자 입력 성공으로 계산하지 않는다.
- **화면 갱신 차이:** clear의 부분 삭제를 전체 삭제로 처리하고 replace는 추가 출력한다. 원본의 행 수 추적과 실제 Emuera 행 수가 다를 수 있다. 선택지나 정보가 사라지는 화면을 추가 검증해야 한다.
- **종료:** 원본 quit API를 JS 세션 정상 완료로 연결했고 호스트 시험을 통과했다. 자동 Emuera 시험은 보고서 후 자신이 만든 프로세스만 종료한다. 일반 게임 메뉴 종료의 성공 근거가 아니다.
- **저장 범위:** JSON/gzip과 재시작 데이터 일치는 검증했지만, 원본 Electron에서 생성한 실제 사용자 세이브의 가져오기·역방향 불러오기는 검증하지 않았다. 원본 로드 메뉴가 진행 흐름을 재구성하는지도 후속 확인이 필요하다.
- **게임 범위:** 새 게임과 휴식 외 훈련·레이스·분기 이벤트 전체를 검증하지 않았다. 미지원 렌더링 형태·모듈·kojo 키가 나오면 오류를 표시한다. 원본은 없는 kojo 키를 로그 후 무시할 수 있으나 이 호스트는 실패시킨다.
- **입력 표현:** hideInput, 자동 넘김, 키 종류·연속 진행 등의 원본 UI 의미가 모두 구현된 것은 아니다. 정규식 오류는 대기 상태를 유지하며 다시 입력받는다.
- **이미지·음성·그래프:** res를 로딩하지 않는다. 표·열은 펼쳐 출력하고 그래프는 데이터 JSON으로 출력한다. 큰 레이스 그래프는 텍스트가 길어질 수 있다. 표시 지연도 생략한다.
- **버전:** 업로드 ZIP의 engine gitlink가 없어 조회한 엔진 커밋을 고정 사용했다. 최신이라는 이유로 임의 업데이트하지 말고 재검증해야 한다.
- **성능:** 게임 프로파일에 큰 메모리·시간 한도를 사용한다. 입력 처리는 협력적이지만 JS 계산 동안 UI가 멈출 수 있다. 32비트 환경·저메모리 PC·장기 플레이는 검증하지 않았다.
- **배포:** 현재 빌드는 로컬 원본 경로를 참조한다. `.kojo` 생성에만 Node가 필요하다. 외부 kojo-loader의 명시적 LICENSE 파일은 조사한 커밋에서 찾지 못했으므로 이 저장소에 컴파일러 자체를 재배포하지 않고 출처와 커밋을 기록했다.

현재 제한을 이유로 게임 규칙을 변경하거나 원본 JavaScript를 대량 수정하지 않았다. 결과물은 후속 호환 작업의 재현 가능한 기반이며 완성된 플레이 배포판은 아니다.
