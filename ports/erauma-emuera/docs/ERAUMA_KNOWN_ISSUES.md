# 원본과의 차이와 검증 제한

이번 호환판은 보존된 era말딸 JavaScript를 Emuera.NET에서 단독으로 실행한다. 게임 규칙을 바꾸거나 원본을 ERB로 다시 작성하지 않았다. 아래 차이와 검증 범위를 유지보수 시 함께 확인한다.

## 표현과 조작 차이

| 원본 EraElectron | Emuera.NET 호환판 | 영향 |
|---|---|---|
| 이미지·배경·오버레이, 음악 | 리소스 미로딩, 이미지 표식과 텍스트, 음악 없음 | 원본의 시각·청각 표현 생략 |
| 이미지 유무에 따른 의상·그림 선택·표시 옵션 | 빈 리소스 맵에서 해당 목록·옵션 생략 또는 비활성화 | 이미지가 필요한 외형·표시 선택의 범위 축소 |
| 여러 열·표·진행 막대 | 행으로 펼친 텍스트와 번호 버튼·수치 | 선택과 데이터는 유지하며 배열 방식 변경 |
| 레이스 차트 | 계열별 시작·종료·최소·최대와 최대 9개 시점의 수치를 텍스트로 표시 | 계산은 원본으로 유지하며 곡선 전체 대신 요약·표본 제공, 표시 수치는 소수점 3자리까지 |
| CSS 색상·정렬·폭·레이어·스크롤 | 기본 Emuera 텍스트 화면 | 원본 레이아웃과 픽셀 단위 일치하지 않음 |
| `era.delay()` 표시 지연 | 즉시 완료 | 크레딧·중간 출력·결과 표시 속도 변경 |
| Shift/연속 진행·UI 자동 넘김 | Enter와 번호·문자열 입력 | 문장 대기를 직접 진행 |
| 제자리 화면 교체 | 논리 행을 교체한 뒤 전체 텍스트 화면 다시 그리기 | 원본의 부분 삭제·행 수 의미는 유지, 시각적인 다시 그리기 발생 |

`setTimeout` 지연 선택지는 실제 경과 시간을 유지한다. 표시용 지연 생략을 게임 이벤트의 타이머 생략으로 확대하지 않는다. 원본의 규칙·데이터 처리는 원본 Era API와 게임 모듈을 재사용한다.

## 확인한 입력과 오류 처리

2026-09-30 사용자가 실제 Emuera에서 `5` → `Trainer` → `Finish`를 입력해 PASS를 확인했다. 결과 파일에도 숫자·문자열·버튼 연결의 정상 완료가 기록됐다. Windows 화면 캡처가 시간 초과되어 이 항목은 사용자 직접 확인과 결과 파일을 근거로 하며 자동 화면 조작 성공으로 기록하지 않는다.

부분 `clear`, 마지막 행 `replace`, 논리 행 수, 이전 버튼 비활성화, 정규식·번호 검사, 대기 입력 교체, 타이머 선택지와 취소를 호환 계층에서 처리한다. 원본에서 보고 후 계속 진행하는 저장 실패·없는 kojo 키는 진단으로 남긴다. 알 수 없는 모듈이나 렌더링 형태, 미처리 JS 오류는 실행 오류로 드러난다.

## 저장과 플레이 검증 범위

원본 API의 JSON/gzip 저장과 새 JS 엔진에서의 복원, 실제 Emuera 프로세스 종료·재실행 뒤 전체 게임 데이터 일치를 검증했다. 원본 Electron으로 만든 사용자 저장을 가져오기와 반대 방향 로드는 검증하지 않았다. 형식과 저장 구현을 재사용했다는 사실만으로 모든 기존 저장과의 상호 운용을 보증하지 않는다.

선택한 새 게임·캐릭터·행동·이벤트 분기를 검증한다. 모든 캐릭터 대사, 난수 이벤트, 장기 엔딩, 모든 언어·설정 조합을 전수 실행한 것은 아니다. 구체적인 완료 경로와 증거는 [이식 현황](ERAUMA_PORTING_STATUS.md)에 기록한다. 원본 Electron과 같은 초기 데이터·난수 조건에서 계산 결과를 비교하는 시험도 아직 수행하지 않았다.

재현용 플레이 시나리오는 시험 안에서 난수를 고정한다. 일반 게임 실행의 `Math.random`은 바꾸지 않는다. 고정 난수로 반복한 호환판 시험은 원본 Electron과의 계산 결과 비교를 대신하지 않는다.

늦게 추가되는 선택지는 호스트의 가상 시간 시험과 실행기의 실제 경과 시간 `AWAIT`/`tick` 시험으로 검사한다. 일반 게임의 타이머 입력은 보이는 창에서 `TINPUTS`를 사용하지만, 해당 입력 대기의 직접 조작은 별도로 확인하지 않았다. 숨겨진 창에서 무인 시험을 실행할 때 `TINPUTS` 내부 타이머가 시작되지 않을 수 있어 시험은 `AWAIT`로 진행한다.

## 버전과 성능

업로드 ZIP에 원본 engine gitlink가 없어 조사한 엔진 API 커밋을 고정했다. 의존성을 업데이트할 때는 원본 게임의 시작·입력·저장·레이스를 다시 검증해야 한다. CommonJS와 Node 호환 기능은 이 게임이 사용하는 범위로 한정한다.

게임 프로파일은 호출당 최대 2GB의 JS 할당, 2천만 문장, 180초 제한을 사용한다. 입력·타이머 대기는 ERB로 반환하지만 JS 계산은 같은 스레드에서 처리하므로 큰 계산 중 화면 반응이 늦어질 수 있다. 32비트 Windows, 저메모리 PC, 장기 플레이의 메모리 증가와 다수 캐릭터 처리 부하는 검증하지 않았다. 성능 관찰치는 시험 조건과 함께 상태 문서에 기록한다.

## 배포와 범위

개발용 `Build.ps1` 출력은 로컬 절대 경로를 참조한다. 배포용 `Package.ps1` 출력은 원본 소스·생성 kojo를 포함하고 상대 경로를 사용한다. Node는 kojo를 빌드할 때만 필요하다. kojo-loader 컴파일러 자체는 명시적 라이선스를 확인하지 못해 재배포하지 않는다.

이미지·음성 복구와 고급 UI 표현은 후속 작업이다. CrossWorld 공용 ID·세계 시간·게임 간 이동·공유 저장은 이번 단독 호환판의 범위에 포함하지 않는다.
